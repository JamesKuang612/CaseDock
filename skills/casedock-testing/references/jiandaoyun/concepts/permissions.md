# 身份与权限

入口缺失时，优先判断权限，不要立刻判断为 UI 缺陷。

## 常见身份

- **企业创建者 / 系统管理员**：通常拥有全产品和全部应用的管理权限。
- **普通管理员**：只能管理被授权的企业范围或应用，能否新增、删除应用还取决于额外授权。
- **应用管理员**：可以设计和管理指定应用，但不等于企业管理员。
- **普通成员**：只能访问已发布给自己的应用、表单、仪表盘和流程。

## 快速判断

| 现象 | 优先检查                                                   |
| --- |------------------------------------------------------------|
| 工作台没有“新建应用” | 是否因为聚焦在搜索应用的框内导致搜索框遮住了新建应用的按钮 |
| 进入应用后没有编辑或应用后台 | 是否拥有该应用的管理权限                                   |
| 看不到数据管理 | 是否为该应用管理员，是否使用电脑端                         |
| 看不到管理后台或通讯录管理 | 是否为创建者、系统管理员或被授权管理员                     |
| 看不到知识库 | 企业版本、是否增购、成员是否有访问权限                     |
| 看不到 AI 能力 | 管理员是否在企业设置中开启 AI 能力                         |
| 开放平台内缺少某项能力 | 账号身份、产品版本、是否增购对应能力                       |

## 测试处理原则

- 用户要求验证“无权限时不可见”，入口缺失可以是正确结果，但必须记录当前身份和可见页面。
- 用户要求完成管理操作而权限不足时，将结果记为 `blocked` 或 `inconclusive`，不要尝试绕过权限。
- 权限不足与产品错误是两类结论。只有获得符合前置条件的账号后仍异常，才进一步判断缺陷。
