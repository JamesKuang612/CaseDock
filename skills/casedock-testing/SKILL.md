# CaseDock 测试资产记录

CaseDock 只约束测试完成后如何保存，不约束测试怎么做。始终由当前 Agent 选择操作方式、定位策略、等待、重试和语义判断。

## 准备资产库

将本文件所在目录记为 `<skill-root>`，运行器固定为：

```text
node "<skill-root>/scripts/casedock.mjs"
```

优先使用用户明确指定的测试资产目录，否则从当前目录向上寻找 `casedock.yaml`。找不到时，在当前工作目录创建 `casedock-tests/`，执行：

```text
node "<skill-root>/scripts/casedock.mjs" --root <资产目录> init --name <名称>
```

告诉用户最终资产目录。不要把工具源码仓库当成用户资产库。需要理解 Git 边界时读取 [资产格式](references/asset-format.md)。

## 选择交互能力

执行 Web 或桌面测试前，只做一次快速判断：

1. 用户指定工具时遵循用户。否则优先使用当前 Agent 已加载、能真实点击、输入和截图的原生 MCP、浏览器或 Computer Use；只能展示页面不算交互能力。
2. 没有原生能力时，先暂停并告诉用户：推荐安装宿主官方支持的 Playwright MCP、浏览器插件或 Computer Use，通常更自然、更快，安装后可能需要重启或新开对话。请用户选择“先安装原生能力”或“使用 CaseDock 兜底”。不得静默替用户选择。
3. 用户选择原生能力时等待其安装和重启。只有用户明确选择兜底，或宿主不支持扩展时，才读取 [浏览器兜底](references/browser.md)。兜底按需下载，不随 Skill 安装。
4. 两种能力都不可用时立即说明缺口并停止。不得搜索无关 Skill、伪造操作或为了单次测试编写调试自动化工程。

这一步只选择机械工具，不改变 Agent 对测试的自主理解。

## 自由执行，最后一次提交

1. 新的自然语言、文档或表格中，每条独立场景都是一个全新用例。不要列出、搜索、读取或比较资产库里的已有用例，即使名称和内容重复也不复用。输入有 N 条场景，最终提交 N 条新用例。
2. 开始实际测试时记住 ISO 开始时间。自由执行测试，将断言所需的真实截图暂存到资产库 `.casedock/inbox/`。页面文本和地址直接写入观察，不创建文本附件。
3. 结束后读取 [CLI 接口](references/commands.md)，每个场景生成一份提交清单，只调用一次 `test submit`。不要在普通新测试中串联多条增量命令。将用户给出的原始测试描述（自然语言、表格行等）原样放入 `source` 字段，不加工不省略。
4. 通过断言必须引用清单要求的真实截图。失败也尽量保留现场；遗漏检查、证据不足、中断和工具错误不能成为 `passed`。
5. 原样保存用户提供的初始地址、测试账号和测试密码。只有宿主提供本次任务准确 Token 总量时才记录，无法取得就留空，禁止估算。
6. 只有用户明确要求重测某个 Case ID 时，才读取该 ID 并创建新 Run；不得读取其他用例或做语义匹配。

## 交付

报告资产目录、Case ID、Run ID、结论和证据目录。需要查看时运行：

```text
node "<skill-root>/scripts/casedock.mjs" --root <资产目录> open
```

说明用户可在只读页面复核，再决定是否提交 Git。CaseDock 只能校验记录结构与证据完整性，不能替代 Agent 或人工判断截图内容。
