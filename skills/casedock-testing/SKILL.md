# CaseDock 测试资产记录

CaseDock 约束测试资产如何保存，不约束测试如何执行。使用当前 Agent 已有的浏览器、计算机操作或其他测试能力；自行选择定位、等待、重试和判断方式。不要安装或切换浏览器执行方案，除非用户要求。

## 找到资产库

从当前目录向上寻找 `casedock.yaml`。用户指定目录时优先使用该目录。若没有资产库但用户明确要求使用 CaseDock，在当前项目下创建 `casedock-tests/` 并运行 `casedock --root <目录> init`；创建后告诉用户实际位置。

读取 [资产格式](references/asset-format.md) 了解版本化内容与临时内容的边界。需要调用记录工具时再读取 [CLI 接口](references/commands.md)。

## 保留 Agent 的执行自由

- 将用例步骤视为业务检查点，不要把它改写成固定的鼠标点击脚本。
- 可以按页面实际情况增加内部操作、等待和恢复尝试；这些不需要成为新的业务步骤。
- 断言结论由实际观察决定。不要把页面当前行为改写成预期，也不要为了通过而降低证据要求。
- 缺少必要能力时如实记录 blocked、error 或 interrupted，不伪造浏览器操作和证据。

## 沉淀用例与运行

1. 查询已有用例，优先复用稳定 ID。用户给出表格、文档或自然语言需求时，将每条独立场景规范化为用例；保留来源文件及行号等可追溯信息于标题、标签或操作描述中，不把凭证写入资产。
2. 在执行浏览器操作前保存用例并开始 run，使本次运行绑定固定用例快照。对同一场景重测时创建新 run，不覆盖历史。
3. Agent 自由执行一个业务步骤后，立即保存实际观察和与断言相关的证据，再继续下一步。不同 Agent 的内部操作可以不同，结果必须按用例中的 step ID 和 assertion ID 对齐。
4. 通过断言必须提交用例要求的证据类型。失败也应尽量保存现场；无法取得证据时如实说明。截图和文本先写到 `.casedock/inbox/`，登记后由 CaseDock 归档。
5. 正常结束、失败结束和中断都要 finish。由 CaseDock 根据已记录内容汇总结论；遗漏检查、证据不足或中断不能成为 passed。

## 交付结果

完成后向用户报告资产库路径、用例 ID、run ID、最终结论和证据目录。提醒用户可运行 `casedock open` 在本地编辑器中复核，再决定是否提交 Git。CaseDock 只能校验格式与证据完整性，不能独立证明 Agent 的语义判断真实。
