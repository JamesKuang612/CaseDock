# CaseDock Skill 架构

## 产品定义

CaseDock 是测试资产与证据协议，不是 Web Agent Harness。任意 Agent 使用自己的交互与推理能力执行测试，CaseDock 将结果保存成一致、可校验、可查看的文件结构。

核心只回答：用例如何版本化、一次执行如何绑定固定快照、观察与证据如何关联，以及缺证据或中断为何不能变成假通过。它不回答如何点击页面。

## 单 Skill 分发

```text
skills/casedock-testing/
├── SKILL.md               Agent 唯一入口
├── references/            渐进加载的协议说明
├── scripts/casedock.mjs   自包含 Core、CLI 和本地服务
├── assets/ui/             编译后的只读页面
└── LICENSE.txt
```

用户安装整个目录即可。运行器不从源码仓库或全局 npm 环境加载依赖；Node.js 22+ 是唯一基础运行时。npm、TypeScript、React、Fastify 和构建脚本只存在于开发环境。

Playwright 是例外的可选能力：它体积大且并非所有 Agent 都需要，因此不打包进 Skill。用户明确选择 CaseDock 兜底后，运行器才通过 npx 按需调用固定版本的官方 Playwright CLI。

## 源码分层

### Skill

`SKILL.md` 负责能力路由和保存流程。入口保持精简，Schema、清单示例、资产边界和浏览器兜底放在 `references/`，仅在需要时读取。

产品知识同样使用渐进加载。简道云知识包先通过轻量索引按用户意图路由，再读取少量概念或导航卡；它只降低页面探索成本，不规定 Agent 的定位策略，也不替代当前页面观察。官方通用知识与公司环境实测信息分开标注，避免把账号权限、灰度界面或企业配置误写成产品通则。

新输入中的每个独立场景都创建全新用例。普通新测试不扫描资产库；只有用户明确指定 Case ID 重测时才读取该用例。

### Core

`src/core` 是业务规则的唯一来源，负责 Schema、唯一 ID、revision、运行快照、原子写入、证据校验和最终结论。任何 CLI、HTTP 或未来 MCP 接口都不能绕开 Core。

### 运行器

`src/cli.ts` 和 `src/server` 经构建合并为 `scripts/casedock.mjs`。普通新测试只需 `test submit` 一次提交完整清单；Core 先校验所有字段和截图，再一次发布 Case 与 Run。增量命令只用于明确指定 Case ID 的重测。

### 本地页面

运行器在回环地址提供只读 HTTP API 和静态 React 页面。页面只展示用例、执行详情与证据，不提供创建、编辑或删除入口，也不需要数据库。

### 交互能力

选择顺序如下：

1. 用户指定的工具；
2. Agent 已加载且能点击、输入和截图的原生 MCP、Browser 或 Computer Use；
3. 告知并等待用户安装宿主原生能力；
4. 用户明确接受后，使用 CaseDock 按需 Playwright 兜底；
5. 均不可用则快速结束并报告能力缺口。

CaseDock 不枚举宿主私有工具，也不静默安装 MCP。兜底只提供可见持续会话和机械操作，不承担规划、定位修复与断言判断。

### MCP

未来 MCP 只能作为 Core 的结构化适配层，改善工具发现和参数传递；不得引入模型 SDK、Agent loop 或第二套业务逻辑。

## 资产生命周期

1. Skill 找到用户指定资产库或 `casedock.yaml`；没有时在安全位置初始化。
2. Agent 快速选择可用交互能力，记录实际测试开始时间。
3. Agent 自由执行，把必要截图暂存到 `.casedock/inbox/`。
4. 每个新场景一次提交用例、执行信息、观察、结论和截图引用。
5. Core 完整校验后生成唯一 Case/Run/step/assertion/artifact ID，冻结用例快照，并将证据复制到最终目录。
6. 正常、失败和中断都保存真实状态；历史 Run 不可覆盖。
7. 人类通过本地页面复核，再决定是否提交 Git。

CaseDock 根据开始时间与提交时间计算耗时。它不参与模型调用，宿主未提供准确 Token 时保持“未记录”，禁止估算。

## 工具与资产边界

源码仓库保存 Skill、实现、测试和示例。用户资产库独立存在，可以是团队 Git 仓库、个人仓库或普通目录。

建议版本化：

- `casedock.yaml`
- `cases/`
- 经审阅的 `runs/` 与证据
- 团队选择仓库级安装时的完整 Skill 目录

默认忽略 `.casedock/` 临时区。大量截图可使用 Git LFS；未来可增加远端对象存储，但结果文件必须保留可迁移引用和哈希。

## 真实性与安全边界

- ID 禁止成为路径片段；所有资产路径限制在工作区内并拒绝符号链接。
- 文件原子替换并使用写锁；用例更新携带预期 revision。
- 证据校验格式、大小与 SHA-256，完成前再次验证。
- 缺少要求证据、步骤未完成或工具中断时，最终结论不能是通过。
- CaseDock 只能证明记录结构和文件完整性，不能证明截图语义判断正确。

当前内部 POC 将测试账号和密码视为普通明文资产，不提供脱敏、加密或提交拦截。
